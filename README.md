# depviz — визуализация графа зависимостей

## Общее описание

Учебный инструмент визуализации графа зависимостей для менеджера пакетов
pip (вариант №10). Программа написана на Java и не использует сторонних
библиотек и менеджеров пакетов.

Выполненные этапы:

- **Этап 1.** Параметры задаются опциями командной строки и
  проверяются на ошибки.
- **Этап 2.** Сбор данных: программа получает из репозитория PyPI
  описание пакета pip и находит его прямые зависимости.
- **Этап 3.** Основные операции: программа строит граф зависимостей
  с учётом транзитивности алгоритмом BFS без рекурсии, корректно
  обрабатывает циклические зависимости и поддерживает режим
  тестирования с файлом тестового репозитория.

## Функции и настройки

### Параметры командной строки

| Опция       | Описание                                         | Обязательна |
|-------------|--------------------------------------------------|-------------|
| `--package` | Имя пакета: в режиме `real` — имя пакета pip (`requests`), в режиме `test` — большие латинские буквы (`A`) | да |
| `--repo`    | URL репозитория (`real`) или путь к файлу тестового репозитория (`test`) | да |
| `--mode`    | Режим работы с репозиторием: `real` или `test`   | нет (`real`) |
| `--output`  | Имя файла с изображением графа (`.svg`)          | да          |

Каждая опция пишется вместе со значением: `--package requests`.
Параметр `--output` пока только проверяется, файл изображения будет
создаваться на этапе 5.

### Построение графа (алгоритм BFS)

Граф хранится как словарь: имя пакета → список его прямых зависимостей.

1. В очередь кладётся анализируемый пакет.
2. Из начала очереди берётся пакет. Если он уже есть в графе,
   он пропускается — так обрабатываются циклические зависимости.
3. Для пакета находятся прямые зависимости.
4. Пакет и его зависимости записываются в граф, а зависимости
   добавляются в конец очереди.
5. Шаги 2–4 повторяются, пока очередь не опустеет.

Обход сделан циклом `while` с очередью `ArrayDeque`, без рекурсии.

### Режим real: зависимости из репозитория PyPI

1. Из URL репозитория и имени пакета составляется адрес JSON-описания:
   `<репозиторий>/<пакет>/json`, например
   `https://pypi.org/pypi/requests/json`.
2. Описание скачивается классом `HttpURLConnection` из стандартной
   библиотеки Java.
3. Прямые зависимости записаны в поле `info.requires_dist` — это список
   требований, например `"idna<4,>=2.5"`. Поле читается своим маленьким
   разборщиком JSON (`RequiresDistParser`), потому что готовые
   JSON-библиотеки сторонние.
4. Из каждого требования берётся имя пакета — начало строки до
   первого знака сравнения, скобки, пробела или `;`.
5. Не учитываются зависимости с условием `extra` (например,
   `PySocks; extra == "socks"`): pip ставит их, только если пользователь
   сам попросил дополнительную возможность пакета.
6. Имена приводятся к единому виду, как в pip: маленькие буквы,
   знаки `. - _` заменяются дефисом (`Charset_Normalizer` →
   `charset-normalizer`).
7. Для каждой зависимости берётся описание её последней версии
   в репозитории.

### Режим test: файл тестового репозитория

Каждая строка описывает пакет и его прямые зависимости. Имя пакета
и зависимости разделяются двоеточием, зависимости — пробелами.
Имена — большие латинские буквы. Пустые строки пропускаются.
Пакет, который не описан в файле, считается пакетом без зависимостей.

Пример (`tests/data/cycle.txt`):

```
A: B
B: C
C: A D
D: D
```

### Обработка ошибок

При ошибке программа выводит сообщение `Ошибка: ...` и завершается
с кодом 1.

| Что проверяется | Когда выводится ошибка |
|-----------------|------------------------|
| опции           | опция неизвестна, указана дважды или у неё нет значения |
| `--package`     | имя не задано, пустое или содержит пробелы; в режиме `real` содержит символы, кроме латинских букв, цифр и `. - _`, или начинается/заканчивается не буквой и не цифрой; в режиме `test` состоит не из больших латинских букв или его нет в файле |
| `--mode`        | значение не `real` и не `test` |
| `--repo`        | не задан; в режиме `real` не начинается с `http://` или `https://`; в режиме `test` файл не существует |
| `--output`      | имя не задано, пустое или не оканчивается на `.svg` |
| загрузка        | нет сети, пакет не найден (код ответа 404), неверный адрес |
| ответ PyPI      | в JSON нет поля `requires_dist` или JSON испорчен |
| тестовый файл   | строка без двоеточия или имя не из больших латинских букв (с номером строки) |

### Классы и методы

`src/Config.java` — параметры программы:

| Метод | Описание |
|-------|----------|
| `parse(args)` | разбирает аргументы и проверяет все параметры |
| `readOptions(args)` | читает пары «опция значение» в словарь |
| `isKnownOption(option)` | проверяет, что опция известна |
| `isBlank(text)` | проверяет строку на пустоту |
| `check()` | вызывает все проверки по очереди |
| `checkMode()` | проверяет режим работы |
| `checkPackage()` | проверяет имя пакета для выбранного режима |
| `checkRepo()` | проверяет URL или путь к тестовому файлу |
| `checkOutput()` | проверяет имя файла изображения |
| `getPackageName()`, `getRepo()`, `getMode()`, `getOutput()` | возвращают значения параметров |

`src/Graph.java` — граф зависимостей:

| Метод | Описание |
|-------|----------|
| `DependencySource.getDependencies(name)` | источник прямых зависимостей (PyPI или файл) |
| `build(start, source)` | строит граф алгоритмом BFS |

`src/PyPi.java` — работа с репозиторием PyPI:

| Метод | Описание |
|-------|----------|
| `makeJsonUrl(repo, packageName)` | составляет адрес JSON-описания пакета |
| `makeUrl(address)` | превращает текст адреса в объект URL |
| `downloadText(address)` | скачивает текст по адресу |
| `getDirectDependencies(repo, packageName)` | скачивает описание и возвращает строки требований |
| `isExtra(requirement)` | проверяет, что зависимость нужна только для extra |
| `readName(requirement)` | читает имя пакета из строки требования |
| `isNameChar(symbol)` | проверяет, может ли символ быть частью имени |
| `normalizeName(name)` | приводит имя к единому виду |
| `getDependencyNames(repo, packageName)` | возвращает имена зависимостей для графа |

`src/RequiresDistParser.java` — чтение поля `requires_dist`:

| Метод | Описание |
|-------|----------|
| `parse()` | возвращает список строк из поля `requires_dist` |
| `findKey()` | находит ключ `"requires_dist"` вне других строк |
| `readArray()` | читает массив строк `[...]` |
| `readString()` | читает строку в кавычках |
| `readEscape()`, `readUnicode()` | читают записи вида `\"`, `\n`, `A` |
| `skipSpaces()`, `current()`, `expect(symbol)` | вспомогательные методы чтения |

`src/RepoFile.java` — тестовый репозиторий:

| Метод | Описание |
|-------|----------|
| `isTestName(name)` | проверяет, что имя — большие латинские буквы |
| `checkTestName(name, lineNumber)` | проверяет имя из строки файла |
| `parseLine(line, lineNumber, repo)` | разбирает одну строку файла |
| `parse(lines)` | разбирает все строки файла в словарь |
| `load(path)` | читает файл тестового репозитория |
| `getDependencies(repo, name)` | возвращает зависимости пакета из файла |

`src/Main.java` — точка входа:

| Метод | Описание |
|-------|----------|
| `main(args)` | запускает программу и передаёт код выхода системе |
| `run(args, out, err)` | проверяет параметры, строит и выводит граф |
| `getStartName(config)` | имя начального пакета (в режиме real — в едином виде) |
| `makeSource(config)` | выбирает источник зависимостей по режиму |
| `makeTestSource(path, packageName)` | создаёт источник из тестового файла |
| `printGraph(start, graph, out)` | выводит граф строками `A -> B, C` |

## Сборка и запуск тестов

Нужен JDK 11 или новее (команды `javac` и `java`). Сторонние библиотеки
не нужны. Скомпилированные классы складываются в папку `build/`.

Сборка:

```
make build
```

Запуск программы (скрипты сами собирают проект):

```
./run.sh --package <имя> --repo <url или файл> [--mode test] --output <файл.svg>
run.bat --package <имя> --repo <url или файл> [--mode test] --output <файл.svg>
make run ARGS="--package <имя> --repo <url или файл> --output <файл.svg>"
```

Запуск тестов (интернет не нужен: тесты запускают на компьютере
поддельный репозиторий):

```
make test
```

или без make:

```
javac -encoding UTF-8 -d build src/*.java tests/*.java
java -cp build AllTests
```

Удаление собранных файлов:

```
make clean
```

## Примеры использования

### Режим test

Граф без циклов: B и C зависят от общего пакета D, F — зависимость
третьего уровня (`tests/data/simple.txt`):

```
$ ./run.sh --package A --repo tests/data/simple.txt --mode test --output graph.svg
Граф зависимостей пакета A:
A -> B, C
B -> D
C -> D, E
D -> нет зависимостей
E -> F
F -> нет зависимостей
```

Граф от пакета в середине:

```
$ ./run.sh --package E --repo tests/data/simple.txt --mode test --output graph.svg
Граф зависимостей пакета E:
E -> F
F -> нет зависимостей
```

Граф с циклом A → B → C → A и пакетом D, который зависит сам от себя
(`tests/data/cycle.txt`):

```
$ ./run.sh --package A --repo tests/data/cycle.txt --mode test --output graph.svg
Граф зависимостей пакета A:
A -> B
B -> C
C -> A, D
D -> D
```

Тот же граф с другого пакета цикла:

```
$ ./run.sh --package C --repo tests/data/cycle.txt --mode test --output graph.svg
Граф зависимостей пакета C:
C -> A, D
A -> B
D -> D
B -> C
```

Ошибки тестового режима:

```
$ ./run.sh --package A --repo tests/data/bad.txt --mode test --output graph.svg
Ошибка: строка 2: имя пакета 'b' должно состоять из больших латинских букв

$ ./run.sh --package Z --repo tests/data/simple.txt --mode test --output graph.svg
Ошибка: пакет Z не найден в тестовом репозитории

$ ./run.sh --package a --repo tests/data/simple.txt --mode test --output graph.svg
Ошибка: в режиме test имя пакета должно состоять из больших латинских букв
```

### Режим real

Вывод зависит от текущих версий пакетов в PyPI:

```
$ ./run.sh --package requests --repo https://pypi.org/pypi --output graph.svg
Граф зависимостей пакета requests:
requests -> charset-normalizer, idna, urllib3, certifi
charset-normalizer -> нет зависимостей
idna -> нет зависимостей
urllib3 -> нет зависимостей
certifi -> нет зависимостей
```

Ошибки режима real:

```
$ ./run.sh --package no-such-package-xyz --repo https://pypi.org/pypi --output graph.svg
Ошибка: не удалось загрузить https://pypi.org/pypi/no-such-package-xyz/json (код ответа 404)

$ ./run.sh --package -requests --repo https://pypi.org/pypi --output graph.svg
Ошибка: имя пакета pip может содержать только латинские буквы, цифры и знаки . - _ и должно начинаться и заканчиваться буквой или цифрой

$ ./run.sh --package requests --repo ftp://example.org --output graph.svg
Ошибка: URL репозитория должен начинаться с http:// или https://
```
